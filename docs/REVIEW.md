# Анализ и проверка проекта

Дата: 20 сентября 2026 года.

## Исходное состояние

Небольшой асинхронный бот на aiogram и SQLite. Сценарий: просмотр каталога, ввод контактов, сообщение менеджеру. README был пустым, автоматических тестов в проекте не было; каталог `tests` исключался из Git.

## Исправления

| Проблема | Результат |
| --- | --- |
| Глобальные идентификаторы навигации общие для всех покупателей | Родительские идентификаторы передаются в кнопках; глобальное состояние убрано |
| Обработчики FSM перехватывали команды | Команды обрабатываются раньше ввода; `/cancel`, `/shop` и `/start` сбрасывают форму |
| Фото или стикер вместо телефона / email вызывали ошибку regex | Нетекстовый и некорректный ввод оставляет пользователя на текущем шаге |
| Товар без картинки нельзя было показать | Добавлена текстовая карточка; длинные описания отправляются отдельно от фото |
| `get_item` возвращал результат выборки вместо одного товара | Возвращается `Item` или `None`; отсутствующий товар обработан явно |
| Регистрация требовала username, хотя его может не быть | Отсутствие username поддерживается без изменения старой таблицы |
| Покупка существовала только в сообщениях со случайным номером | Заказ сохраняется в БД с первичным ключом и снимком товара / контактов |
| Сбой Telegram прерывал оформление | Сохранённая заявка остаётся доступной; недоставленное уведомление отмечается в БД |
| Повторный ввод мог создавать повторную покупку | Добавлены уникальный ключ оформления и изоляция событий одного пользователя |
| Токен и адресат уведомлений находились в коде | Настройки читаются из окружения; запуск проверяет обязательные значения |
| Импорт `run.py` создавал Telegram-клиент | Клиент создаётся внутри `main`, ресурсы закрываются в `finally` |
| Git отслеживал локальную конфигурацию, `.pyc` и `.exe` | Эти файлы удалены из индекса и исключены из дальнейшего отслеживания; локальные копии сохранены |

Доступ к базе отделён от клавиатур, проверка контактов выделена в отдельный модуль. Убраны неиспользуемые импорты, повторные имена функций и состояний, дублирующие запросы и общие перехваты `Exception` с показом ошибки пользователю.

## Проверка

Локальное окружение: Windows, Python 3.14.5, aiogram 3.31.0, SQLAlchemy 2.0.54, aiosqlite 0.22.1.

Результат: **28 тестов прошли** (`python -m unittest discover -s tests -v`). Проверки `ruff check` и `ruff format --check` также прошли.

Автоматические проверки:

- Полный заказ через `Dispatcher.feed_update`, включая запись пользователя и уведомление менеджера.
- Повторный покупатель, подсказки контактов и сохранение прежних данных в снимке заказа.
- Два покупателя с разными разделами и независимыми формами оформления.
- Повторный email, параллельные запросы создания заказа и уникальность результата.
- Все команды выхода на каждом шаге FSM; `/help` и неизвестная команда сохраняют шаг.
- Нетекстовые сообщения, некорректные имена, телефоны и email.
- Пустой каталог, отсутствующие товары, удаление товара во время оформления.
- Карточки с изображением и без него; длинное описание вне подписи фотографии.
- Некорректные и устаревшие callback-кнопки.
- Ошибка записи в БД с последующей успешной повторной попыткой.
- Ошибка доставки менеджеру с сохранением заявки и завершением формы.
- Игнорирование групповых сообщений и сброс неполного состояния формы.
- Создание демокаталога с нуля, повторное заполнение, импорт без побочных эффектов и запуск без токена.

Тесты работают с временными базами; Telegram API заменён тестовым транспортом. Это проверка логики приложения и маршрутизации, а не реальная доставка Telegram-сообщений или корректность байтов фотографии. Рабочая база не изменялась, реальные сообщения не отправлялись. Проверки GitHub Actions добавлены, но результат облачного CI появится только после отправки изменений в GitHub.

## Оставшиеся ограничения

В README описаны отсутствие оплаты, корзины, админ-панели, пагинации и повторной доставки уведомлений; хранение FSM в памяти; работа одним процессом; отсутствие системы миграций. Это направления дальнейшего развития, а не уже реализованные функции.

В прежнем отслеживаемом `config.py` найдено значение формата Telegram-токена. Его действительность не проверялась. Исключение файла из текущего индекса не удаляет его из прошлых коммитов: владельцу нужно перевыпустить токен через BotFather. История Git в рамках этой работы не переписывалась.
